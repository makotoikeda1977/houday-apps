# アプリ2: 有給休暇マスター（付与日数・時効・5日義務・残日数管理） slug=yukyu-master OWNER=放デイの書類屋さん（houday.jp）
目的: 小規模事業所の経営者・事務が、社員ごとの年次有給休暇の付与日・日数・時効消滅日・年5日取得義務の期限を自動計算し、取得日を登録して残日数を管理できる（労基法39条）。
## 制度データ（app.js内で定数化）
- 通常付与（週所定30時間以上 または 週5日以上 または 年217日以上）: 勤続6か月10日、1年6か月11日、2年6か月12日、3年6か月14日、4年6か月16日、5年6か月18日、6年6か月以上20日。
- 比例付与（週30時間未満 かつ 週4日以下 または 年216日以下）:
  週4日(年169〜216日): 7,8,9,10,12,13,15
  週3日(年121〜168日): 5,6,6,8,9,10,11
  週2日(年73〜120日): 3,4,4,5,6,6,7
  週1日(年48〜72日): 1,2,2,2,3,3,3
- 付与要件: 雇入れから6か月継続勤務＋全労働日の8割以上出勤（画面で「出勤率8割未満の年」はチェックで付与0日にできる）。
- 時効: 付与日から2年（付与日の2年後の応当日の前日まで）。繰越は翌年度1回のみ（未消化は2年で消滅）。
- 年5日取得義務: 付与日数10日以上の労働者は付与日から1年以内に5日取得（使用者の時季指定義務、労基法39条7項、未達は30万円以下の罰金）。比例付与で10日未満は対象外（繰越分含めて10日以上でも対象外＝当年付与分で判定）。
- 消化順序: 初期設定は「古い付与分から消化(FIFO)」。設定で「新しい分から(LIFO)」に切替可（就業規則による）。
- 統一基準日制度: 設定で「基準日を毎年4月1日等に統一」を選べる（入社後最初の法定基準日以降は統一日に前倒し付与。前倒しの場合は次回付与を短縮した期間で扱う簡易実装でよい。初期はオフ）。
- 年次有給休暇管理簿: 基準日・日数・取得時季を記録し5年保存（当分の間3年）。
## 画面
1. 社員一覧（左/上）: 氏名、入社日、区分（週30h以上・週5日以上=通常 / 週4日 / 週3日 / 週2日 / 週1日）、任意で年間所定日数。追加/編集/削除。Freeは3名、Proで無制限。
2. 社員詳細: 付与スケジュール表（第n回・付与日・付与日数・時効消滅日・5日義務期限・5日義務の達成状況）を今日から2年先まで表示。付与日ごとに「8割未満で不付与」チェック。
3. 取得登録: 日付＋日数（1 / 0.5=半日）を追加、一覧、削除。残日数はFIFO/LIFOで付与ロットに割り当て。
4. KPI: 現在の残日数／今年度の取得日数／5日義務の残り日数と期限／時効で消える予定の日数（次の消滅日と日数）。
5. アラート一覧（全社員横断）: 5日義務の期限が90日以内で未達、時効消滅が60日以内で残あり、付与日が30日以内。
6. 出力: 「管理簿を印刷」（社員別：基準日・付与日数・取得日一覧・残）、「CSV出力（全社員）」＝Pro、「JSONバックアップ/復元」＝全員可。
7. 使い方 .note: 法定最低基準であり就業規則で上回る場合はそちらが優先。
テスト観点（実装後に自分でconsoleで検算）: 2020/4/1入社・通常 → 2020/10/1に10日、2021/10/1に11日、…、2026/10/1に20日。2020/10/1付与分の時効=2022/9/30。週3日入社2024/1/10→2024/7/10に5日。
